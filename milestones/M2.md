# M2 — Validation (JPL Horizons) and frame correctness
Read `AGENT.md` first.

**Goal:** prove the Sun/Earth angles are right and show the measured error in the app. **People:** 1. Independent of M1 (positions do not depend on terrain). After finishing, take the IM-1/IM-2 replay (optional) or help M1 with the frame/longitude test.
**Owns:** `pipeline/ephemeris.py`, `pipeline/validate_horizons.py`, `pipeline/tests/`, the validation section of `src/pages/Method.jsx`, `public/data/validation.json`. **Must not edit:** site data.

## Steps
1. Run `python pipeline/validate_horizons.py` on a machine with internet (a Horizons request per site/time; parser is the fragile part, expect to fix it on the first run). Output: `public/data/validation.json`.
2. Confirm the MOON_PA -> MOON_ME offset (67.92", 78.56", 0.30", sign -1) against the real NAIF frame kernel (`moon_080317.tf`) or a Horizons check; fix constants in `ephemeris.py` if different.
3. Decide error thresholds and state them on the Method page with the measured values (max/mean error for Sun and Earth az/el over the sampled times).
4. Confirm leap-second assumption (TAI-UTC = 37 s) still holds for 2026-27.
5. (Optional) Mission replay: IM-2 (Mons Mouton, 2025) or Chandrayaan-3, only with facts verified from official sources; separate JSON + component, no edits to `sites.json`.

## Done when
`validation.json` exists, Method page shows measured error (no "not yet run"), frame offset verified or the caveat stated.
